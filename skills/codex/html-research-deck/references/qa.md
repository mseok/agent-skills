# QA and delivery

All commands run from the skill directory with absolute paths; `CHROME` may point at another Chromium build. Outputs go under the deck folder's `qa/`, never into the skill.

```sh
python3 scripts/check_deck.py /abs/deck/index.html --json /abs/deck/qa/check.json   # exit 1 on grid/citation/copy errors
python3 scripts/check_layout.py /abs/deck/index.html --json /abs/deck/qa/layout.json # measured boxes: text outside its panel, label collisions, rim crossings, closing-line wrap, empty bands
scripts/shots.sh /abs/deck/index.html /abs/deck/qa/shots 0.5                        # one PNG per slide, final build state
scripts/shots.sh /abs/deck/index.html /abs/deck/qa/shots-full 1                     # full size for the inspection pass
sh scripts/contact_sheet.sh /abs/deck/qa/shots /abs/deck/qa/contact.png 5           # whole deck on one image
scripts/export_pdf.sh /abs/deck/index.html /abs/deck/qa/deck.pdf                    # one 1440×810 pt page per slide (?print mode)
python3 scripts/pdf_compare.py /abs/deck/qa/deck.pdf --json /abs/deck/qa/pdf-compare.json   # Poppler and Ghostscript renderings side by side; exit 1 on a flagged page or an unembedded font
python3 scripts/banned_copy_lint.py /abs/deck/index.html --json /abs/deck/qa/banned-copy.json  # exit 1 on a banned copy pattern
python3 scripts/regression_run.py                                                   # replays every recorded user-reported defect; exit 1 on FAIL; run it again after any change to a checker or the theme
```

`check_layout.py` renders the deck once in headless Chrome and measures every text run, shape, line, path, raster and HTML block in stage pixels. Errors (exit 1): text leaving its panel, the stage or its `<svg>` viewport (clipped), text in the 20 px padding, two labels or a label and an HTML block overlapping, a label crossing a rect / circle / ellipse / polygon rim it does not sit inside, a `<line>`, `<path>`, `<polyline>` or `<polygon>` running through a glyph box (reference lines, chart curves, arrowheads, trapezoid edges), a label on a raster, a shape or image leaving its viewport, a clipping HTML block whose content scrolls (a formula wider than its `.fx.box`), two slide-level HTML blocks intersecting (the title slide's h1 over its subtitle, a wrapped h2 over the panels), a title or closing line that wraps, a formula that did not render (a `.katex-error` span, or `\cmd`, `$…$` or an HTML entity such as `&gt;` still visible as text), text inside a box within 6 px of its left or right edge (3 px top or bottom). Warnings: text off-centre inside a box, text below 4.5:1 contrast against what it sits on (3:1 for bold text ≥ 22 px; the cite line against the stage — the theme's `--muted` is `#66727F`, 4.9:1 on white, since the v5 judge called 3.0:1 grey notes unreadable at 2 m), a formula strip spanning ≥ 60 % of the panel whose left and right gaps differ by > 16 px, two shapes ≥ 24 px overlapping without nesting, and the fill of each panel — the top gap (panel edge to the first glyph, ≈27 px with a lane header at y 24+4) and the bottom gap must stay within 24 px of each other and under 80 px. **Delivery gate: zero errors, and every warning either fixed or named with its reason in the report.** Why: the first CausalGame deck (2026-10-31) shipped with 100–170 px empty bands and reference lines through value labels, and the first Latent SI deck (2026-11-01) passed with 0/0 while its title wrapped over the subtitle, chart curves ran through value labels and a label was cut by the panel edge — HTML blocks, paths and clipping were not measured then, which the user called out ("왜 캐치를 못했는지 모르겠고 앞으로 이런 거는 반드시 캐치하도록"); its v5 then passed 0/0 while slide 20 showed `\beta &gt; 0` in red (a card path html-escaped the `&gt;` a second time, so KaTeX received `&`), slide 17's `+ 잡음 0.1` touched both sides of its box and slides 8–10 had formula strips 20 px from one panel edge and 60 px from the other — the independent judge found all three, the checker none, hence the three kinds above. Fix the layout in the builder, not by shrinking type: enlarge the figure, use the type scale in `design-system.md` (24 px base, nothing under 22 except reference notes and a 30-row chart), move a label to the side of a curve where the curve is not, and cut commentary to two or three lines per panel.

Inspection pass (the part no script does): open every full-size PNG; look for rows of equal things with unequal spacing or misaligned edges, table rules that run past the last column, arrowheads detached from their line, uneven inner margins, a panel row with different heights, raw `$…$` where KaTeX did not render, a density raster with its dots off the cloud, anything that reads as decoration. Fix in the builder or `index.html`, re-shoot the touched slides, look again. Then open two PDF pages at low resolution (`pdftoppm -r 48`) to confirm gradients, shadows and fonts survive printing (`pdffonts` lists Pretendard as embedded). `pdf_compare.py` does the same on every page with two renderers; open both renderings of each page it flags, and name any flag you leave in the report. The MANUAL lines of `regression_run.py` are the defects no script measures: check each one on the full-size PNGs.

Publish (Mac mini): copy the deck into a clean bundle with `deck.pdf` beside `index.html`, run the host's `publish.py` with `--entry index.html --slug <talk>-<date>[-vN]`, then verify the served state — `curl` the local URL and `cmp` the bytes with the source `index.html`; request every asset the page needs (css, js, fonts, each figure, `deck.pdf`) and expect 200 with the right sizes; request the HTTPS URL with `--resolve` to the Tailscale address and expect 200 with `ssl_verify=0`. Give the user the HTTPS link first and the local link second. Previous slugs stay online; name the current one.

Report format: done/blocked per requested slide; what was verified (check_deck result, PNGs inspected, PDF pages and fonts, served bytes identical, assets 200, HTTPS verified); what was not (keyboard interactions such as the presenter window, other browsers); visible word count per slide from `check_deck.py` when the user is watching text density; and any scientific content you added beyond the approved storyline, as a question, never silently.

Research-talk gates still apply before delivery: the fact-check list (every number, comparison, citation and claim mapped to its source) and the Korean copy rule; `check_deck.py` covers the markers and endings mechanically, not the truth of the claims.
