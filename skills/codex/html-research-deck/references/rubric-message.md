# 메시지 채점표 (100점) — 2026-10-31 고정본

출처: 사용자 피드백 2026-10-31("디자인은 이제 좋네. 이제 메시지만 좀 조절하면 되겠다. 멘트같은것들이 내가보기에는 너무 technical 해보이고 academic paper or work 를 발표하는 스타일은 아닌거같은데 … yuanqi du 거의 맥락과 포인트들을 잘 살펴보고 … 기준을 만들고 계속 스킬을 개선해줘")과 `message-style.md`(레퍼런스 덱 분석). 디자인 채점표(`rubric.md`)와 별개로 문구만 잰다. 한 번 고정되면 점수를 올리려고 기준·문턱·배점을 바꾸지 않는다(정직성 규칙). 측정은 `scripts/score_message.py`, 심사는 덱을 만들지 않은 별도 모델이 문구 덤프·논문 초록·전체 보기 한 장만 보고 한다(`judge-message-prompt.md`).

## 적용 범위

- 대상: 표지(1장)와 마지막 정리 장을 제외한 내용 슬라이드. 정리 장은 M4·M7과 심사 N3·N5에만 들어간다.
- 점수 = 측정 50 + 심사 50. 통과선은 앞선 goal과 같은 **90점**(사용자가 정한 기준을 이어받음). 메시지 점수가 90을 넘어도 디자인 점수(`score_deck.py`, 신선한 심사)가 90 아래로 떨어지면 통과가 아니다.

## 심사 항목 (독립 심사자, 문구 덤프 + 논문 초록 + 전체 보기 한 장, 50점)

|---|---|---|---|
| N1 | 요점이 제목과 마무리줄에 | 12 | 제목이 그 장의 요점을 청중의 말로 말하고(절 이름·변수 나열·"A: B" 라벨 구문 아님), 마무리줄이 교훈 한 문장 또는 증거 숫자 하나이며 제목의 되풀이가 아니고 "저자 결론:" 같은 라벨 접두사가 없음. 장마다 0–2 → 평균/2 × 12 |

## 정직성 규칙

1. 이 파일, `judge-message-prompt.md`, `score_message.py`, `deck_copy.py`의 SHA-256을 `deck/qa/rubric-message-frozen.json`에 고정한다. 해시가 다르면 점수는 무효(기준 변경). 기준을 바꾸려면 사용자 승인을 먼저 받고 다시 고정한다. (기록: 2026-10-31 21:15 첫 고정 뒤 기준선 심사에서 인용줄 위치 표기가 N2로 감점되는 모순이 드러나 1회차 시작 전에 이 줄만 고치고 21:3x에 다시 고정했다 — 반복이 돌기 전의 수정이며 점수를 올리려는 변경이 아니다.)
   (기록 2: 2026-10-31 21:5x, 1회차 심사 중 사용자 지시 "A:B 이런 스타일로 왜이렇게 많이 쓰는거지? 최대한 안 쓰면 좋겠는데" → M8 신설(4점), M1·M3을 10→8로 줄여 측정 합계 50 유지, N1 문구 보강, 다시 고정. 사용자가 직접 요청한 기준 변경이며, 1회차 점수는 새 기준으로 계산된다.)
   (기록 3: 2026-10-31 22:38, 2회차 심사 중 사용자 지시 "(발표자 비유) (게임 한 판) 이런 의미 없는 괄호도 빼줘" → M9 신설(4점: 숫자 없는 괄호 금지), M4(b)를 "괄호 풀이" 보상에서 "용어를 쉬운 말로 바꿔 쓰지 않은 비율" 감점으로 바꿈, M7은 인용줄 표기만 인정, M6·M7을 6→4로 줄여 측정 합계 50 유지, N2 문구 보강, 다시 고정.)
2. 심사(N1–N5)는 덱을 만든 세션이 아닌 별도 모델 실행이 문구 덤프·초록·전체 보기만 보고 한다. 심사 원문은 `deck/qa/judge-msg-<timestamp>.json`에 그대로 보관한다. 빌더는 심사 파일·점수 파일을 쓰거나 고칠 수 없다.
3. 슬라이드 수와 승인된 스토리라인의 `id`·`role`·`evidence`는 `work/storyline-v1.json`과 같아야 한다(제목·메시지·마무리줄·전환은 바꿀 수 있음 — 사용자 지시 2026-10-31). 장을 지우거나 합쳐서 점수를 올리지 않는다.
4. 디자인 채점표의 고정 해시(`deck/qa/rubric-frozen.json`)도 그대로여야 하고, 메시지 반복마다 디자인 점수를 신선한 심사로 다시 잰다. 통과 = 메시지 ≥ 90 **그리고** 디자인 ≥ 90, 둘 다 valid.
5. 숫자는 늘 논문 인쇄값. 문구를 바꾸면서 새 수치를 더하지 않고, `fact_check.py`를 매 반복마다 다시 돌린다. 저자의 주장을 발표자의 생각으로, 발표자의 생각을 저자의 주장으로 바꿔 적지 않는다.
6. 최종 관문은 사용자 본인의 검토다. 90점은 "보여 줄 준비가 됐다"는 뜻이지 승인이 아니다.
