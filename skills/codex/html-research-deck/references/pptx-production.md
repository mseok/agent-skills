# PPTX route: editable PPTX and PDF in the dissertation style

Read this file only when the user asks for PPTX, PowerPoint or Keynote output, or edits an existing PPTX deck. The storyline, its approval, the fact-check gate, the completion list and the revision rules are in SKILL.md and apply unchanged; this file replaces only the production step. It is the former `research-talk` skill's production part, moved here on 2026-11-12 with its wording kept. The design reference is `pptx-design.md`, verification is `pptx-qa.md`, the kit is `assets/pptx/` and its scripts are `scripts/pptx/` (paths relative to the skill folder; reference files named without a folder are in `references/`).

## Precedence

This skill's rules override the Presentations skill's generic style guidance where they differ: editable causal diagrams and labels, native arrows/connectors, and coordinate-based PyMOL/RDKit figures for structural claims are required here; suitable anatomical illustration may use GPT Image, and the dissertation palette, composition recipes and closing interpretation line replace generic “clean slide” advice. They also override `artifact-template-seokhyun-research/design.md` and the style-reference artifact's README below wherever they differ (for example fonts: this skill's single family is Pretendard even if those say Helvetica Neue or Apple SD Gothic Neo; footer sizes and colours likewise). English slide copy keeps the author's own punctuation and wording (em dashes, “→”, semicolons, “ · ”); the Presentations skill's copy-style bans do not apply, and the Korean noun-phrase rule applies to Korean slides only. Use the Presentations skill for Artifact Tool mechanics, export and finalization only.

## Brief-driven runs

In a brief-driven run (SKILL.md, Brief-driven runs) the deck font is Pretendard for English and Korean alike (`createDeck()` needs no language switch). Harness-only steps of the Presentations skill (`mark_artifact_operation_started.mjs`, workspace-dependency loaders) are skipped outside Codex; use the runtime paths from the brief.

## Build after approval

1. Read `pptx-design.md` and the installed Presentations skill. Resolve the registered artifact template using `pptx-template-location.json`. Use its clean reusable PPTX. The unmodified dissertation is a fidelity reference, not automatic content for the new talk.
2. Materialize local `storyline.json` using `storyline-format.md`. Run `scripts/check_storyline.py` before deck creation. It checks the approved snapshot; separately verify that its approval reference is a real user decision.
3. Import and duplicate suitable clean template slides, or use `assets/pptx/style-kit.mjs` with Artifact Tool for native objects; read `assets/pptx/kit-demo.mjs` first: `slide(..., takeaway:)`/`closing()`, `stage()`, `thinArrow()`, `findings()`, `rich()` with `[[red|key phrase]]`, `barChart()`/`scatterChart()`, `table()` (markup cells), `credit()`, auto-sized titles, `references()`, `figureLabel()`/`leader()`, `containRect()` give the dissertation's composition (see `pptx-design.md` “Composition recipes”). When using the style kit, copy it into the presentation build directory beside the runtime node_modules link so its package import resolves locally. Preserve measured design and editability. Discover layouts by name, not array index: this runtime includes default masters/layouts in the same collection. Follow Presentations export and finalization with `assets/pptx/finalize.mjs` (run beside the runtime `node_modules` link; the draft lives inside `--workspace`): charts need their embedded workbooks, and without them Apple's renderer (QuickLook, Keynote preview) draws no chart. Render the finalized deck with a second renderer too (`render_ql`-style QuickLook) and compare, since per-point chart fills and chart text sizes are dropped by Apple's engine (`barChart()` keeps one honest data series and highlights with a per-point fill; QuickLook drops that fill, so report it as an open Keynote risk).
4. Choose the visual from the explanatory task and the presenter's expertise, following `pptx-design.md`. For a mechanism sequence, start with one biological scene and causal map, reuse its spatial anchors across overview and detail slides, and place each paper beside the specific relation or observation it supports. Read the mechanism-continuity guidance in `pptx-design.md`; do not turn the scene into independent ingredient rows or disconnected pages. Use GPT Image when anatomical context benefits from illustration, keeping scientific labels, causal links and citations editable. For this user's biology talks, prefer molecular structure and binding explanations they can explain confidently. Honor an explicit structural-explanation request with an identified structural/chemical interaction view, not protein-name boxes alone. For a mechanism, depict the same substrate in its changed states with actors and transitions; a static protein view beside prose is insufficient when the message concerns change. Original paper panels are useful when their assay and readout are the actual subject, not simply because a paper contains an image. Do not use unfamiliar microscopy as a default background visual. For protein structures, pockets or complexes use actual coordinates rendered in PyMOL; read `molecular-visualization.md`. Distinguish measured structural evidence from explanatory schematic elements. Preserve the biological evidence and its citation without implying that a molecular pose proves a cellular phenotype. Rebuild charts/tables only from actual data; preserve units, subsets, conditions and uncertainty. Mark missing inputs specifically. Never manufacture results. Example-deck numbers are not evidence for unrelated talks.
5. Apply the current presentation defaults even when importing an older template: 1.2× line spacing, single native arrow shapes or arrow-ended connectors, and one verified font family — Pretendard, the default for Korean and English decks on Mac and Windows; `createDeck()`/`finalize.mjs` auto-install it via `scripts/pptx/ensure_font.py` — across editable Korean/Latin/Greek text, and visible external references matching the apparent size of the previous Helvetica Neue 20pt (Pretendard 20pt) in the lower right. Keep author notation in the original Latin form, including `et al.` on Korean slides. Cite external figures and claims using compact author–journal–year or APA style; no reference is needed for this study's own results. Map each external claim, named compound and reused panel to its source at the point of use; read `citations.md`. Number references from [1] by first appearance, then renumber all linked objects after any reorder. Optically center molecular/node labels in their own native shapes and use meaningful shape distinctions as specified in `pptx-design.md`. A footer bibliography alone is insufficient. Put full citations, figure/panel identifiers, Obsidian paths, experiment IDs and host-qualified asset locations in speaker notes. Preserve visible disclosures that affect interpretation. Keep build/debug commentary in local QA records, outside the talk.
6. For Korean slide copy, use concise noun phrases rather than declarative endings such as “~한다”; follow `korean-slide-copy.md` and run `scripts/pptx/check_korean_slide_copy.py` against the exported PPTX. Resolve findings before delivery. This rule covers titles, subtitles, body text, captions and tables, not the spoken script.
7. Render the PPTX to PNGs and run `scripts/pptx/check_layout_quality.py deck.pptx --renders DIR` (dissertation-derived floor: evidence fills the content band, no dead zones, closing interpretation line, text ≥ 24 pt, one font family, no text-on-footer overlap); fix every finding by enlarging/recomposing the evidence, not by padding text. Run `scripts/pptx/check_slide_conventions.py` on the exported PPTX and resolve citation-number/diagram-alignment findings, then run the rendered-ink alignment check and inspect the native/PDF rendering for optical centering. Verify that every residue used as structural evidence is highlighted and labelled beside its visible site. Deliver a separately named PPTX and matching PDF. Render every slide and follow `pptx-qa.md`. Inspect PowerPoint and representative Keynote pages when available. Report only native-app checks actually performed.

## Hosts, existing decks and native apps

- Production tools: the Codex Presentations plugin with the registered template on the Mac; the `pptx` skill or `python-pptx` with the clean reference deck copied locally elsewhere. If the template or design-system artifact is unreachable in the current harness, say so once and build with a local copy; never skip the approval step because a tool is missing.
- On a host without the Artifact tool (for example the lab server), go straight to this PPTX build path; ship `reference.pptx` and a one-time export of the design-system bundle inside the skill's assets, resolved relative to the skill directory.
- Existing-deck edits: pull in the deck's own source PPTX template and the user's style reference first; the remaining existing-deck rules are in SKILL.md.
- Rendering and QA run from scripts under a timeout (`open -a`, Keynote AppleScript export, scripted PowerPoint save-as-PDF), never by driving Open or Export dialogs; if PowerPoint verification fails once, stop retrying, name the blocking app state and the one user action that unblocks it, and label every layout check "Keynote/PDF only". A property claimed about the rendering is measured on the exported PDF or PNG, never on XML attributes.
- `assets/pptx/finalize.mjs` and `assets/pptx/style-kit.mjs` find the skill's scripts through `$RESEARCH_DECK_SKILL` (the older `$RESEARCH_TALK_SKILL` is still read), then the skill folder they sit in, then `~/.codex/skills/html-research-deck`; set the variable when working from a frozen copy.
