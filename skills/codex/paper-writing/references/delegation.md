# Packaging the work for a writer

A writer agent or model sees only what it is given. The package must let a writer with no other context produce the text the plan describes, and no part of it may be a summary that loses a number, a condition or a placement.

## The package

Put the files in one folder. Keep facts in notes.md and editorial decisions (tiers, placements, framing) in plan.md.

The source package is complete so the writer can make informed choices; the manuscript is selective in service of its argument. Preserve facts in the package without requiring every fact to appear in the main prose. Results that change a claim's meaning remain visible with that claim; other details follow their agreed placement.

- **`notes.md`**: the facts, in any language, with a source locator for each (file, table, run). Every number with its unit, comparator, condition, basis, aggregation and uncertainty, and its figure or table number if one exists, copied from its source, never rounded or paraphrased here. Keep conflicting values, missing definitions, the author's interpretations ("저자 정리: …") and unrun work, each marked as such, and each result's status (planned, run or independently re-verified) with any later correction. Leave out only what bears on no claim: keep every result that tests, bounds or contradicts a claim or belongs to a reported aggregate.
- **`plan.md`**, when there is one: the plan (`planning.md`) with its status. An "accepted" plan carries the author's words of acceptance; an unreviewed plan says "provisional". Without a plan, leave the file out, and the writer makes the decisions privately.
- **`brief.md`**: the exact target venue and article type; intended readers and assumed knowledge; the author's scientific purpose and the supported contribution; useful editorial choices and disciplinary usage from matched examples, with the passages actually inspected and explicit access to their complete Introduction or opening prose (`venue-adaptation.md`); the sections to write and their file names; target lengths if known; spelling; output format; citation placeholders; the language of Notes to author; and whether figure and table numbers are the paper's own. Supply actual opening prose privately where permitted or verify that the writer can access the named sources. Summarized style rules alone are insufficient; full-main-narrative analyses provide context for the reading. Keep the context concise, distinguish official requirements from examples, and keep published full text out of public skill files and final deliverables. A writing exemplar is not automatically a manuscript citation.
- **`prompt.txt`**: the prompt below with every brace filled in, saved beside the package together with the skill snapshot's path and hash and the model and reasoning effort requested, so the run can be repeated or audited.

## The prompt

Fill in the braces and give the writer this prompt, adjusted only where the harness differs:

```
You are drafting parts of a research paper. No one will answer questions before the text is due: do not stop to ask, and do not return a plan instead of the files.

Inputs: read only {DIR}/brief.md, {DIR}/plan.md and {DIR}/notes.md, the matched source-reading material explicitly named in brief.md, and the skill folder named below. Open nothing else under {ROOT}, and in particular nothing under {FORBIDDEN}. Do not browse the web. Do not put the user's email address, phone number or account IDs into any external request (web search, URL, API call).

Read the writing skill directly from {SKILL}: SKILL.md first, then references/register.md including its contrasting examples, and the references for the sections you write. Apply the supplied journal and reader context; the coordinator has handled source discovery. Before a new draft, examine the complete Introduction or opening prose in the supplied matched sources; use their editorial analyses as context, not as substitutes for reading. Preserve the author's scientific purpose while calibrating its claims to the evidence. Before returning the draft, follow references/integration.md using the sections and context provided. Do not invoke the Skill tool, do not read references/planning.md or references/delegation.md, and use no other installed skill or MCP tool. Skip the skill's planning discussion and independent source discovery: follow plan.md as far as its status allows (an accepted plan binds the direction; a provisional plan is a proposal), except where it conflicts with notes.md or the non-negotiables; there, follow the evidence and report a material departure in Notes to author. The coordinator performs the mandatory final reference-verification pass after integration; do not claim that the isolated draft has received it.

If a shell is available, run python3 -I {SKILL}/scripts/check_prose.py DRAFT --notes {DIR}/notes.md --section SECTION on each draft, with SECTION one of intro, methods, results or other. If you compute values, create {OUT}/working-notes.md containing the unchanged source notes followed by labeled computations with operands, units and basis, and pass that file to --notes instead. Do not modify source notes or append routine arithmetic to the manuscript or Notes to author merely to satisfy the checker. Reread each report and fix real problems; a review item is a prompt to check, not an instruction to delete.

Write the scientific message directly for the readers named in brief.md, using the field's language and the target article format. Keep your checks, evidence-status labels and irrelevant untested extensions out of the prose; retain conditions and findings that affect its meaning without repeating qualifications already clear from context. Create {OUT} and write {OUT}/<section>.md for each requested section. Each file holds manuscript text only; actionable author issues go after a line --- under the heading Notes to author.

Final reply: the file paths and their word counts, nothing else.
```

- Before launching, obtain the relevant journal sources and examples, resolve factual conflicts where possible, and check that the writer can read every input path, the matched opening prose and the skill path and can write `{OUT}`. If the writer will use verified online source access, adjust the prompt's browsing and tool restrictions to permit only source-reading access to those named articles. Nothing may depend on implicit skill discovery, a slash command or another session's history. Do not pass a checklist of unrelated untested claims as the paper's outline.
- `{SKILL}` is an absolute path the writer can read. For a comparison, make it a frozen copy of the skill for this run and record its path and a hash of its files, so every writer reads the same version. `{ROOT}` is the project folder; `{FORBIDDEN}` names every folder the writer must not see, such as the source papers of a test.
- If no plan is supplied, drop plan.md from the inputs line and replace its direction instruction with: "Make the four decisions privately from notes.md and the supplied journal context, then write the sections."
- For a condition without the skill, replace the skill and checker paragraphs with "Do not use any installed skill: do not invoke the Skill tool and do not read skill files from ~/.claude/skills, ~/.codex/skills, ~/.gemini/config/plugins, ~/.gemini/antigravity/skills or ~/agent-skills." Keep every other line identical, and give plan.md only if the comparison is meant to include it. In Codex, that condition must not have the skill installed under `~/.codex/skills`, and `{OUT}` must lie inside the session's writable roots.
- Use the same model and reasoning effort for every compared condition, give every writer the same package and prompt except for the factor being compared, and write each output to its own folder. In a test, plan.md is written from notes.md alone, by someone who has not read the source paper.
- For a chat interface without file access, send one message that contains brief.md, plan.md and notes.md inline, followed by the skill's SKILL.md and the references for the requested sections (or attach those files), with the same private source-reading material where permitted or verified usable source access. Ask for the manuscript text and the Notes to author block.
- Read each returned draft against notes.md and plan.md before using it: the numbers with their basis, the scientific meaning in context, material contrary findings and the planned placements. Check that the central message is clear and that the draft does not narrate the review process. Integrate the manuscript and run the final reference-verification pass on the actual deliverable.
