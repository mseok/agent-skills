# User-requested fresh-context evaluation

Use this workflow when the user explicitly asks to test the skill from a completely new context and improve it from the resulting artifact.

Freeze the current skill and record its file hashes. Prepare a minimal task brief containing the actual user requirements, approved language/storyline and raw evidence locators. Preserve scientific corrections and approval provenance. Exclude prior conversation transcripts, previous generated decks/builders, the evaluator’s diagnosis and a suggested visual solution. The producer must discover what the skill instructs from the skill itself. Do not conceal required raw evidence merely to make the test difficult.

Before handoff, compare that brief with the latest explicit user corrections. Preserve required comparisons, denominators, assigned slide topics and requested omissions as content constraints. A fresh context removes conversational history and old design decisions; it must not discard accepted requirements. Broad slide messages alone may omit a required evaluation component. Distinguish a deficient handoff brief from a failure of the producing skill when reviewing the result.

Start a genuinely separate context (an independently spawned agent with no inherited turns or a user-requested new task). Give it the skill, brief, raw inputs and isolated output directory. Do not claim an in-place reread or a rewritten prompt is a fresh context. Have it create the requested artifact without editing the skill. Ask for output paths, source/citation mapping, visual review and concrete blockers; keep implementation commentary outside the presentation.

Review the first independently produced artifact before intervening. Retain the first result and a concise evaluation: actual slide/object, expected requirement, observed behavior, and evidence. Separate a missing skill rule from an execution lapse, unavailable source/tool or evaluator preference. Improve only the demonstrated gap, then test the relevant change without overwriting the first output. Necessary factual fixes to a deliverable do not require making every finding a new permanent skill rule.

Use the same method for later user-authorized iterations. Do not automatically create a new task or spend on repeated whole-deck runs for every routine edit.
